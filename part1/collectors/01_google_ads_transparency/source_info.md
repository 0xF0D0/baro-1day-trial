# 소스 1: Google Ads Transparency Center

- 확인일: 2026-11-10
  - 이 스레드: `deathwishcoffee.com` 광고 30건, 상세 3건 (미국 IP, 화면이 뜨는 Chrome)
  - 메인 스레드: 5개 브랜드 도메인 광고 693건, 페이지 넘김, 헤드리스 실행. 근거는 `part1/collectors/01_google_ads_transparency/spec.md` 2절이다. 아래에서 "(spec)"으로 표시한다.
- 표기: ✅ 실제 응답에서 확인함 / ❓ 추정이거나 미확인
- 수집기 구현 요구사항은 spec이 기준이다. 이 문서는 조사 결과와 결정을 담는다.

## 1. 이 소스가 주는 것
Google(검색, YouTube, 디스플레이 등)에 집행된 광고 소재 목록이다. **한 행은 광고 소재 1개**다.

## 2. 접근 방법
- 주소: `https://adstransparency.google.com/?region=US&domain=<브랜드 도메인>&hl=en`
- 로그인이 필요 없다. 한국 IP와 미국 IP 모두 열린다 ✅. 헤드리스 Chrome에서도 목록, 페이지 넘김, 상세가 모두 된다 ✅(spec).
- 페이지를 열면 페이지가 스스로 아래 요청을 보낸다. 그 응답을 가로채서 저장한다. 첫 목록 요청은 같은 내용으로 두 번 나간다 ✅(spec).

| 요청 | 언제 나가나 | 담긴 것 |
|---|---|---|
| `SearchService/SearchCreatives` | 목록 페이지를 열 때, 그리고 다음 페이지를 불러올 때 | 광고 목록(한 번에 최대 40개) |
| `LookupService/GetCreativeById` | 광고 상세 페이지를 열 때 | 그 광고의 변형(variation) 전체 |
| `LookupService/GetAdvertiserById` | 광고 상세 페이지를 열 때 | 광고주 이름과 국가 |

### 페이지 넘김 ✅(spec)
- 40건을 넘으면 응답에 다음 페이지 토큰(키 `2`)이 온다. 마지막 페이지에는 `2`가 없다.
- 다음 페이지는 화면의 "See all ads"를 한 번 누른 뒤 아래로 스크롤하면 불러온다. 스크롤마다 요청이 하나 나가고, 그 요청 본문의 키 `4`가 앞 응답의 `2`와 같다. `list_batiste_page1.json`의 `2`와 `list_batiste_page2.json` 요청의 `4`가 글자 그대로 같다 ✅.
- 이 방법으로 Batiste 67건 중 67건, Living Proof 232건, Jinx 319건을 끝까지 받았다.

### 요청 수 (브랜드 하나)
- 목록: 광고 40건마다 1회.
- 상세: 마지막 노출이 최근 7일 이내인 광고만 1회씩(10절 결정).
- 스크립트 미리보기: 이름을 남기는 광고주(3절 표)의 광고만, 상세에서 스크립트 형태인 변형마다 일반 GET 1회.
- 재시도는 하지 않는다. 실패한 요청은 기록만 하고, 다시 돌리는 것은 파이프라인이 정한다(`part1/collectors/README.md` 0절).
- 첫 실제 실행(2026-11-10 11:08Z, 미국 IP, 헤드리스)에서 두 가지가 막혔고, 원인을 확인해 고쳤다 ✅.
  - **속도 제한:** 페이지를 3초 간격으로 열면 약 9번째 상세 페이지가 HTTP 429로 온다(Google의 실제 속도 제한). 간격을 10초로 늘리니 Death Wish 상세 33건을 모두 받았다.
  - **목록 멈춤:** 스크롤을 한 번만 하면 다음 쪽 요청이 나가지 않을 때가 있어 120건(3쪽)에서 멈췄다. 2.5초마다 다시 스크롤하니 Living Proof 232건을 헤드리스로 끝까지 받았다.

## 3. 브랜드 매칭
- **도메인으로 찾는다.** 광고주 이름으로 찾으면 모회사의 다른 브랜드가 섞인다. Batiste는 Church & Dwight 명의이고, 이름 검색 결과는 약 3,100건이다.
- Batiste 도메인의 광고 67건은 모두 광고주 계정 하나(`AR09009539290362806273`, Church & Dwight Co., Inc.)에서 나왔다 ✅(`list_batiste_page1.json`, `page2`). 이전에 적었던 "Batiste는 계정 4개"는 틀렸다.
- 도메인 검색은 광고주가 누구든 그 도메인으로 보내는 광고를 모두 잡는다 ✅. `deathwishcoffee.com` 30건 중 26건은 Death Wish Coffee LLC, 4건은 Simplifi Holdings, LLC(대행사) 명의다. `blackriflecoffee.com` 36건에는 광고주가 20곳이고, 개인 실명 광고주도 섞여 있다 ✅(spec). 광고주 조회 응답으로는 개인인지 회사인지 가릴 수 없다.
- 결정(2026-11-10, 사용자 승인): 광고주를 가리지 않고 모두 넣는다. 아래 "이름을 남기는 광고주"가 아닌 광고주는 이름을 지우고 ID만 남긴다. 개인 실명일 수 있어서다.
- 한계: 브랜드 도메인이 아닌 곳(리테일러 사이트 등)으로 보내는 광고는 잡히지 않는다 ❓.

## 4. 원본 구조
응답은 필드 이름 없이 숫자 키만 있는 JSON이다. 아래 뜻은 화면과 대조해서 붙였다.

### 4-1. 목록 응답 (`samples/list_*.json`)
| 키 | 뜻 | 예시 | 근거 |
|---|---|---|---|
| `1[]` | 광고 배열 | 30개 | ✅ 한 응답에 최대 40개 |
| `2` | 다음 페이지 토큰 | `CgoAP7zm...` | ✅ 다음 페이지가 있을 때만 온다 |
| `4`, `5` | 전체 개수의 하한과 상한(문자열) | `"67"`/`"67"`, `"200"`/`"300"` | ✅ 정확하면 둘이 같고, 많으면 다르다. Living Proof는 200/300이고 화면은 "~300 ads"였다(spec) |
| `1[].1` | 광고주 ID | `AR06827167829175828481` | ✅ 상세 주소에 쓰인다 |
| `1[].2` | 소재 ID | `CR07113068967253508097` | ✅ 상세 주소에 쓰인다 |
| `1[].3` | 미리보기 | 아래 4-3 참고 | ✅ |
| `1[].4` | 포맷 | `1` 텍스트, `2` 이미지, `3` 영상 | ✅ 상세 화면의 "Format" 3건과 일치 |
| `1[].6.1` | 처음 노출 시각(초 단위) | `1787688093` = 2026-08-25 | ❓ 화면에 표시되지 않는다. 키 `13`과의 관계로 추정했다 |
| `1[].7.1` | 마지막 노출 시각(초 단위) | `1794278752` = 2026-11-10 02:45 UTC | ✅ 화면의 "Last shown: Nov 9, 2026"(미국 시간)과 일치 |
| `1[].12` | 광고주 이름 | `Death Wish Coffee LLC` | ✅ |
| `1[].13` | 노출된 날 수 | `76` | ❓ 처음~마지막 사이 일수(UTC 날짜 기준)와 대체로 같거나 작지만, 30건 중 3건은 1 크다. 화면에 없어서 뜻을 확인할 수 없다 |
| `1[].14` | 도메인 | `deathwishcoffee.com` | ✅ 샘플 167건 모두 요청한 도메인과 같다 |

- 광고 항목의 키는 언제나 `1`, `2`, `3`, `4`, `6`, `7`, `12`, `13`, `14`다 ✅(5개 브랜드 693건, spec).
- 목록은 마지막 노출이 최근인 순서로 오고, 몇 달 전에 끝난 광고도 들어 있다 ✅.
- 광고가 없는 도메인의 응답은 `{}`이다 ✅(`list_zero.json`).

**날짜 주의:** 키 `6`, `7`은 UTC 시각이고, 화면은 미국 시간 날짜를 보여 준다. 위 예시는 UTC로 11월 10일이지만 화면에는 "Nov 9, 2026"으로 나온다. 값이 서로 틀린 것이 아니라 같은 순간을 다른 시간대로 적은 것이다. 상세 응답의 `1.17[].5`는 확인한 2건 모두 `20261109`로, 화면 표기와 같은 날짜다 ✅. UTC 날짜만 저장하면 사이트와 하루 어긋나 보인다.
화면은 보는 사람의 시간대를 따르지 않는다. 확인 당시 브라우저는 한국 시간(11월 10일)이었는데 화면은 Nov 9였다 ✅. 미국 동부와 서부 중 어느 쪽 날짜인지는 확인한 3건으로 가릴 수 없다 ❓. 그래서 사이트와 대조할 날짜는 시각을 직접 변환하지 않고 `1.17[].5`를 그대로 쓴다. 이 값은 상세를 연 광고에만 있다. 처음 노출은 이에 해당하는 날짜 값이 없어서 UTC 시각만 있다.

### 4-2. 상세 응답 (`samples/detail_*.json`)
| 키 | 뜻 | 예시 |
|---|---|---|
| `1.1`, `1.2` | 광고주 ID, 소재 ID | |
| `1.4.1` | 마지막 노출 시각 | 목록과 같다 |
| `1.5[]` | 변형 목록 | 텍스트 광고 1건에 변형 3개 ✅ |
| `1.8` | 포맷 | 목록의 `4`와 같다 |
| `1.17[]` | 지역별 정보 | `{"1": 2840, "5": 20261109}`: 2840은 미국, 뒤는 화면에 표시되는 마지막 노출일 |
| `1.22.1` | 광고주 이름 | |

`1`의 키는 `1`, `2`, `4`, `5`, `8`, `17`, `22`뿐이다 ✅.

변형 하나(`1.5[i]`)는 두 형태 중 하나다 ✅.

| 형태 | 모양 | 샘플 |
|---|---|---|
| 이미지 | `{"3": {"2": "<img src=...>"}}`. `"5": true`가 함께 붙는 경우가 있다 | `detail_text_3_variations.json`, `detail_video.json` |
| 스크립트 | `{"1": {"4": "<content.js 주소>"}}` | `detail_script_video.json` |

- 상세의 스크립트 주소는 목록 항목의 스크립트 주소와 다르다 ✅(spec).
- 스크립트 주소는 로그인 없이 일반 GET으로 60~150KB의 JavaScript를 돌려준다. 6.5시간 전에 받은 주소도 200을 돌려줬지만 언제 만료되는지는 모른다 ❓(spec). 그래서 수집기는 수집할 때 본문을 받아 둔다.

### 4-3. 미리보기의 두 형태
목록 항목의 `3`과 상세 변형은 같은 두 형태를 쓴다. 경로만 다르다.

| 형태 | 목록 항목 안 | 상세 변형 안 | 내용 | 목록 30건 중 |
|---|---|---|---|---|
| 이미지 | `3.3.2` | `5[].3.2` | `<img src="https://tpc.googlesyndication.com/archive/simgad/...">`. 그대로 내려받을 수 있다 ✅ | 27 |
| 스크립트 | `3.1.4` | `5[].1.4` | `content.js` 주소. 실행하거나 본문을 뜯어야 내용이 나온다 | 3 |

스크립트 3건의 포맷은 이미지 1, 영상 2다. 영상 3건 중 나머지 1건은 이미지 형태로 오지만 내용은 빈 재생기 그림이다. 스크립트 형태로 오는 이미지 광고에서 실제 이미지 주소를 얻는 방법은 확인하지 않았다 ❓.

## 6. 지금 돌고 있는 광고의 판정
수집기는 판정하지 않는다. 원본만 저장하고, 판정은 뒤의 파이프라인이 실행 결과끼리 비교해서 한다(`part1/collectors/README.md` 5절).

목록에는 끝난 광고도 섞여 있다. Death Wish 30건의 마지막 노출일 분포는 아래와 같다.

| 마지막 노출 | 건수 |
|---|---|
| 11월 8~10일 | 24 |
| 11월 6일 | 1 |
| 10월 22일 | 1 |
| 9월 1일 | 4 |

- 판정 기준은 스키마 단계에서 정한다(10절). 조사 때의 제안은 "마지막 노출이 수집 시각 기준 3일 이내면 active"였고, 이 기준이면 24건이 active다.
- 상세를 여는 범위(최근 7일, 10절)는 판정 기준과 별개다. 상세를 열지 않은 광고에도 목록 정보로 레코드가 남는다.

## 7. 항목 식별과 재실행
- 고유 키: `<광고주 ID>/<소재 ID>`
- 대조용 주소: `https://adstransparency.google.com/advertiser/<광고주 ID>/creative/<소재 ID>?region=US`
- 수집기는 실행마다 새 파일을 쓰고 이전 실행의 파일을 고치지 않는다. 같은 키의 갱신과 ended 표시는 파이프라인이 실행끼리 비교해서 한다.

## 10. 결정
### 확정 (2026-11-10)
1. 미디어(이미지와 영상): 파일은 받지 않고 주소만 둔다. 종류(image / video)를 함께 적는다. 과제가 미디어 파일을 요구하는 소스는 TikTok과 Meta이고, 이 소스에는 그 요구가 없다. 스크립트 미리보기 본문은 미디어 파일이 아니고, 주소가 만료될 수 있어서 수집기가 받아 둔다(4-2).
2. 상세 범위: 마지막 노출이 수집 시작 기준 최근 7일 이내인 광고만 상세를 연다. 그보다 오래된 광고는 목록 정보만 레코드로 남긴다. 과제가 "지금 도는 광고"를 요구하기 때문이다.
3. 광고주 이름: 3절 표의 광고주(브랜드 본인 계정과 Death Wish의 대행사 한 곳)만 이름을 남긴다. 나머지는 이름을 지우고 ID만 남긴다.
4. 스크립트 미리보기 본문: 이름을 지우는 광고주의 광고는 받지 않는다. 본문에 광고에 표시되는 이름(개인 실명일 수 있음)이 들어 있을 수 있어서다(들어 있는지는 확인하지 않았다). 그 광고의 스크립트 형태 변형은 미디어 주소와 YouTube ID를 얻지 못한다.

### 스키마 단계에서 정한다
원본 수집기는 원본을 그대로 저장하므로, 아래는 수집기 구현에 영향이 없다.
1. 텍스트 광고의 문구: 그림 주소에서 멈출지, 글자 인식까지 할지. (제안: 글자 인식까지. 과제가 "text"를 요구한다)
2. active 기준. (제안: 마지막 노출 3일 이내)
3. 날짜: UTC 시각만 둘지, 화면 표기 날짜(`1.17[].5`)도 함께 둘지. (제안: 둘 다. 사이트 대조에는 화면 표기 날짜를 쓴다. 4-1 "날짜 주의" 참고)
4. `days_shown`을 둘지. 과제가 요구한 항목이 아니고 뜻을 확인할 수 없다. (제안: 뺀다)

## 11. 선택한 attribute
2026-11-10 검토에서 정했다. 한 행은 광고 소재 1개이고, 변형은 그 안에 목록으로 담는다. 원본 안의 위치는 spec 10절과 같다.

| attribute | 원본 위치 | 예시 | 비고 |
|---|---|---|---|
| creative_id | 목록 `2` | `CR07113068967253508097` | 고유 키 |
| advertiser_id | 목록 `1` | `AR06827167829175828481` | 고유 키의 일부 |
| advertiser_name | 목록 `12` | Death Wish Coffee LLC | 모회사 명의인지 구분한다. 3절 표에 없는 광고주는 지워져서 비어 있다 |
| domain | 목록 `14` | deathwishcoffee.com | 브랜드 매칭의 근거 |
| format | 목록 `4` | 텍스트 / 이미지 / 영상 | 과제 요구 항목 |
| first_shown_at | 목록 `6` | 2026-08-25 | 과제 요구 항목. 화면에 없어서 대조할 수 없다 |
| last_shown_at | 목록 `7`. 화면 표기 날짜는 상세 `17[].5` | 2026-11-10 | 과제 요구 항목. 저장 방식은 10절 |
| days_shown | 목록 `13` | 76 | 노출된 날 수(추정). 둘지 말지 미확정(10절) |
| variations[] | 상세 `5[]` | 3개 | **확정.** 변형마다 미디어 종류와 주소를 담는다. 최근 7일 안에 노출된 광고만 상세를 열어서 채운다. 나머지는 비어 있다 |
| variations[].media_type | 미리보기 형태와 포맷 | image / video | **확정.** 종류만 가른다 |
| variations[].media_url | 상세 `5[].3.2`의 `src`. 스크립트 형태는 받아 둔 본문 안 | `https://tpc.googlesyndication.com/archive/simgad/14162868596355023513` | **확정.** 파일은 받지 않고 주소만 둔다. 텍스트 광고는 광고 모양을 그린 그림의 주소다. 이미지 형태로 온 영상은 빈 재생기 그림의 주소다. 이름을 지우는 광고주의 스크립트 형태 변형은 본문을 받지 않으므로 비어 있다(10절). 주소를 얻지 못한 변형은 비워 두고 그 사실을 표시한다 |
| variations[].text | 그림에서 글자 인식 | 헤드라인, 설명문, 표시 주소, 하위 링크, 가격, 평점 | 과제 요구 항목. 원본에 글자로는 없다. 할지 말지 미확정(10절) |
| youtube_video_id | 받아 둔 스크립트 본문 안 | `Khsp2wp_XwA` | 영상 광고 중 일부에서만 얻는다 |
| detail_url | ID 두 개로 조립 | `https://adstransparency.google.com/advertiser/<광고주 ID>/creative/<소재 ID>?region=US` | 실제 사이트와 대조하는 주소 |
| is_active | 파이프라인이 판정 | true | "지금 도는 광고" 판정. 기준 미확정(10절) |

변형이 왜 필요한지는 `samples/text_ad_preview.png`, `text_ad_variation_2.png`, `text_ad_variation_3.png`를 비교하면 보인다. 같은 광고인데 헤드라인이 다르고, 2번에는 하위 링크의 오퍼("Free 10oz Bag of Vanilla, With Any Order")와 가격("from $11.99")이, 3번에는 판매자 평점("4.8 ★ (3K)")이 붙어 있다.

### 버리는 것
- 지역 코드: 미국만 조회하므로 항상 2840이다. 지역별 마지막 노출일(`17[].5`)은 화면 표기 날짜라서 버리지 않는다.
- 미리보기 이미지의 가로·세로 크기
- 광고주 조회 응답 전체. 이름은 목록 항목(`12`)과 상세(`22`)에 이미 있다. 광고주 국가는 쓰지 않는다.

### 원본에 없는 것
랜딩 주소, 행동 유도 문구, 노출량, 광고비, 노출 지면. 미국 광고의 노출량은 상세 응답에도 없다(키는 `1`, `2`, `4`, `5`, `8`, `17`, `22`뿐이다).
